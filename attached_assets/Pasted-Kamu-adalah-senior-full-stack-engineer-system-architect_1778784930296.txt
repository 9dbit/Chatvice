Kamu adalah senior full-stack engineer, system architect, dan product auditor untuk project Chatvice.

Project context:
Chatvice adalah platform AI customer service dan live chat yang memiliki admin dashboard, AI agent, merchant dashboard, chat inbox, user management, dan rencana integrasi ke banyak website/merchant. Sekarang Chatvice ingin diintegrasikan dengan dashboard panel gaming agar Chatvice bisa membaca data transaksi deposit, withdraw, status turnover, saldo player, histori transaksi, dan status bonus secara aman.

Tugas utama kamu:
1. Audit dulu sistem admin dashboard Chatvice yang sudah ada.
2. Identifikasi fitur yang sudah tersedia, belum tersedia, rusak, kurang aman, atau perlu dikembangkan.
3. Buat dan terapkan to-do list teknis untuk membangun Gaming Panel Integration.
4. Implementasikan struktur halaman, komponen, database schema, API route, webhook receiver, security layer, dan UI dashboard yang dibutuhkan.
5. Jangan menghapus fitur existing kecuali memang broken atau duplicate.
6. Semua perubahan harus production-minded, aman, modular, dan siap dikembangkan menjadi multi-merchant.

PHASE 5: WEBHOOK RECEIVER
==================================================

Create webhook endpoint:

POST /api/webhooks/gaming/events

Supported event types:

deposit.created
deposit.success
deposit.failed
withdraw.requested
withdraw.approved
withdraw.rejected
turnover.updated
balance.updated
bonus.claimed
bonus.expired
player.suspended
player.verified

Webhook payload example:

{
  "event_type": "deposit.success",
  "event_id": "evt_123456",
  "merchant_id": "gunungmas88",
  "player_id": "GM8899123",
  "username": "adwin123",
  "transaction_id": "DEP-20260515-0001",
  "data": {
    "amount": 500000,
    "currency": "IDR",
    "status": "success",
    "payment_method": "QRIS"
  },
  "timestamp": "2026-05-15T01:45:00+07:00"
}

Webhook requirements:
- Verify HMAC signature
- Verify timestamp
- Prevent replay attack
- Validate merchant ID
- Save raw payload
- Process event
- Update related transaction table
- Trigger AI/customer notification rules
- Log success/failure
- If failed, move to failed events table
- Support retry mechanism

Headers:

X-Chatvice-Merchant-ID
X-Chatvice-Signature
X-Chatvice-Timestamp
X-Chatvice-Event-ID

PHASE 8: AI AGENT BEHAVIOR
==================================================

Add safe AI data access policy.

When customer asks:
"Deposit saya sudah masuk belum?"

AI flow:
1. Identify logged-in user.
2. Check player mapping.
3. Fetch latest deposit status.
4. If data found, answer with status.
5. If pending, explain politely.
6. If failed, escalate if needed.
7. Never expose internal payload.

When customer asks:
"Withdraw saya kenapa ditolak?"

AI flow:
1. Check latest withdraw.
2. Check turnover status.
3. If turnover insufficient, explain remaining turnover.
4. If rejected by finance, show safe reason.
5. If unclear, escalate to human CS.

When customer asks:
"Turnover saya kurang berapa?"

AI flow:
1. Get turnover data.
2. Show required, current, remaining.
3. Show percentage.
4. Explain eligibility for withdraw.

Example AI answer:

"Turnover Anda saat ini Rp3.250.000 dari total syarat Rp5.000.000. Sisa turnover yang perlu diselesaikan adalah Rp1.750.000. Setelah terpenuhi, withdraw dapat diproses sesuai ketentuan."
